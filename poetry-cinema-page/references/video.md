# video —— 口播视频参考

把第 4 步生成的场景图、第 5 步生成的朗诵音轨（及逐行时间轴 sidecar）、第 6 步页面里的
设计 tokens，合成为一支 1920×1080 / 30fps 的口播成片。工具入口：`scripts/video.py`。

方法论来自 [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft)（及其口播姊妹篇
video-talkcraft）的已验收实践，按诗词语境重新调校。下面按"先想清楚再动手"的顺序展开。

---

## 1. 与宣传片片种的本质区别：先有人声，后有镜头

产品宣传片是**先排动画、再配声音**；口播片是**先有一条人声，把画面钉上去**。

权威时间轴永远是 `narration.py build` 产出的 sidecar
（`public/audio/<slug>.mp3.json`，逐行 `start` / `end` / `duration`）。
`video.py build` 只做一件事：把这些秒数换算成帧号，再决定每一行落在哪张图上。

由此推出两条纪律：

1. **重新生成配音后必须重跑 `build`**，旧时间轴对新音轨毫无意义。
2. **镜头边界钉在静默中点**，不在人声上切——相邻两句之间的间隙
   （行间 0.75s / 段间 1.6s，见 `narration.audio`）就是天然的切换窗口，
   交叉溶解放在这里，观众永远不会看到"画面切在字中间"。

---

## 2. 素材纪律：视频层不生产内容

| 素材 | 来源 | 视频层做的事 |
| --- | --- | --- |
| 场景图 | 第 4 步 `ark_image.py`（hero 参考链） | 原样使用，不裁不拼 |
| 人声 | 第 5 步 `narration.py` | 原样铺底 |
| 色板 / 字体 | 页面 `styles.css` 的 `:root` tokens | 原样继承 |
| 原文 / 释义文本 | 第 2 步 scene-map | 进字幕，不改动 |

视频层唯一"创作"的东西是**运镜**——而这恰恰要克制。图片已经是完整构图，
摄像机的职责是让画面呼吸，不是把观众视线从主体上拽走。位移幅度上限约
画面的 ±1.4%，推拉范围 1.06–1.18×。

## 3. `video-plan.json`（制作放行文件）

每支片子一份 plan，放在诗歌项目根目录（如 `demo/<slug>/video-plan.recitation.json`）。
写这份 plan 就是"制作放行"：它决定哪句话配哪张图、每个镜头做什么运镜。

```jsonc
{
  "slug": "jiang-jin-jiu-recitation",
  "title": "将进酒", "author": "李白", "era": "唐 · 天宝", "genre": "乐府歌行",
  "closing": "沉浸式古诗词页面 · 图像与朗诵由 AI 生成",

  "audio":   "public/audio/jiang-jin-jiu-edge.mp3",
  "timing":  "public/audio/jiang-jin-jiu-edge.mp3.json",
  "images_dir": "public/generated/jiang-jin-jiu",
  "workspace": "video",

  "fps": 30, "width": 1920, "height": 1080,
  "crossfade_frames": 14,
  "tail_seconds": 3.2,
  "grain_opacity": 0.075,
  "motion_gain": 1.0,          // 全局运镜倍率：1 标准 / 1.3 更冲 / 0.6 更含蓄
  "handheld_px": 3.6,          // 手持微抖幅度（像素），0 关闭
  "caption_reveal": true,      // 原文层是否逐字点亮（释义层始终整行淡入）

  "palette": { "ink": "#0d0f10", "moon": "#e6e2d6", "gold": "#d9a84e",
               "amber": "#a8641f", "ochre": "#b8763a" },
  "font": { "serif": "…页面 --font…", "sans": "…释义层…" },

  "original_lines": ["君不见，黄河之水天上来，奔流到海不复回。", "…"],

  "shots": [
    { "image": "hero.jpg",    "role": "title", "lines": [1],    "move": "settle",
      "fx": "quiet",       "transition": "crossfade" },
    { "image": "scene-1.jpg", "lines": [2],    "move": "pull-out",
      "fx": "mist",        "transition": "push-through" },
    { "image": "scene-3.jpg", "lines": [4, 5], "move": "rise",
      "fx": "ember",       "transition": "flash-warm" }
  ]
}
```

字段说明：

- **`shots[].lines`** — 该镜头覆盖的 sidecar 行号（1-based）。要么全部镜头都写，
  要么全部省略；缺省时自动分组，规则见下。
- **`shots[].move`** — 运镜名，见第 4 节；省略或 `auto` 按镜头序号轮转。
- **`shots[].transition`** — **进入这个镜头**的转场，见第 5 节。`shot 0` 写什么都无所谓。
- **`shots[].fx`** — 镜内气层预设或对象，见第 6 节；省略为 `auto`。
- **`shots[].seed`** — 覆盖派生种子。只在需要让某镜的抖动/呼吸换个相位时用。
- **`original_lines`** — 原诗全文。用于字幕角色判定：这句话逐字出现在原诗里 →
  `verse`（大号衬线）；否则 → `prose`（小一号释义）；标题镜头里的行 → `title`。
  **不猜站位**：朗诵稿通篇是原文，讲解稿原文与释义交替，两种稿子的角色分布完全不同。
- **`role: "title"`** — 恰好一个镜头。该镜头放片头字卡，并替掉同名字幕
  （大标题和朗读字幕同框是自我重复）。
- **`tail_seconds`** — 人声结束后留给片尾字卡的时长。直接切黑会让片子像被拔了电源。
- **`palette` / `font`** — 省略时用页面 tokens 的内置默认。
- **`_note` / `_readme` / `_classification_note`** — 任意下划线开头的键都被忽略，
  用来在 plan 里写创作意图。**转场和气层为什么这么分，写在这里**——
  这份 plan 是"制作放行文件"，理由要和决定放在一起。

自动分组规则（省略 `lines` 时）：

1. 按 sidecar 的 `paragraph` 切成连续段；段数恰好等于镜头数 → 1:1 映射
   （讲解稿"每段＝原文＋释义"的情况，正是为它设计的）；
2. 否则按句数均匀分配。

朗诵稿只有 4 个段落却有 8 张图，会走均匀分配——**那不是你想要的**，
所以朗诵版必须显式写 `lines`，并按 scene-map 的分段来。

## 4. 运镜词库

十三个动作，按镜头序号轮转（`auto`），全片才读起来像一个摄影组拍的。
轮转次序刻意打散方向与轴：连着两个 `push-in` 会被读成"卡住了"。

| move | 走势 | 适合 |
| --- | --- | --- |
| `push-in` | 1.15→1.26 推近 | 聚焦一个主体、情绪收紧（铜镜、高歌） |
| `pull-out` | 1.26→1.15 拉开 | 揭示尺度（黄河大远景） |
| `creep` | 1.15→1.21 极慢推 | 长镜头、需要"一直在动但看不出来" |
| `drift-left` / `drift-right` | 横移 ±5.5% | 空间信息多的画面、双层景深 |
| `arc-left` / `arc-right` | 弧线横移 + 纵向抛物 | 绕过前景、带出纵深 |
| `rise` | 上抬 5% + 推近 | 视线升向月亮、天空 |
| `tilt-up` / `tilt-down` | 纯垂直摇 5.8–6.2% | 人物 → 天、远景 → 前景 |
| `settle` | 1.24→1.15 落定 | 片头字卡、全诗终点 |
| `sway` | 横向轻摆 + ±0.28° 滚转 | 微醺、宴饮、非稳定感 |
| `breath` | 极轻的浮动 | 情绪平缓的过渡镜头 |

### 为什么 scale 都在 1.15–1.26 之间

图与画面同为 16:9，`scale = 1` 就刚好铺满，可平移空间只有 `(s-1)/2`。
旧版把 scale 压在 1.06–1.17，位移只剩 ±1.4%——**观众根本看不出在动**，
整片读起来就是"图片 + 字幕的幻灯片"。把基线抬到 1.15 以上等于主动裁掉
原图边缘 13%，换来 ±7% 的平移余量；`transformAt` 的钳位（按**当前帧**
scale 算 `width*(scale-1)/2 × 0.88`）保证任何一帧都不露黑边。

**上限锁在 1.26，这是被实测逼出来的。** `settle` 原来从 1.31 起（裁掉 24%），
在《将进酒》终镜那张破晓图上，人物的幞头顶端被画框切掉了——那张图是
居左人物 + 大远景，裁掉 12% 的顶部就切到人。1.26 对应每边 10.3%，
是"远景里头顶还在画框内"的上限。以后想加幅度，先拿远景 + 贴边人物的图试。

幅度够不够？实测 1.32→1.16 这 11% 的缩放，同镜头内人物变小约 15%、
整体右移 4.6%（1920 宽下约 88px），肉眼一眼可辨。所以不需要更狠。

push-through 的入场额外放大有 `MAX_ENTER_SCALE`（1.42）封顶：
`pull-out` 起点本来就 1.26，再叠 14% 会把主体切出去。

### 两段式行程（`twoPhase`）

**这一条是"不再平铺"的核心。** 旧版是整镜匀速滑到底，Motion 分布太均匀，
眼睛很快把它归成静止背景。现在每个镜头拆两段：前 `settleAt` 帧走完
90% 的行程（一次能被看见的移动），剩下 10% 用几乎停滞的速度慢慢收。
于是每个镜头都有**明确的落点**——移到位置、停住、画面开始呼吸。

`settleAt` 还会按镜头长度自适应（`clamp01((frames-150)/500)` 在 0.66→0.84 之间插值）：
196 帧的短镜利落收住，822 帧的终镜绵长收住。都按 0.66 算的话，
长镜最后五六秒会读成"卡住了"。

### 手持微抖

`transformAt` 每个镜头叠一层两个不同频率（周期 1.4–3.5s）的正弦，
幅度 `handheld_px`（默认 3.4px，约画面宽的 0.18%）+ ±0.07° 滚转。
极轻，但把"CG 输出"变成"有人在掌机"。设 0 关闭。

`motion_gain` 是全局倍率，**只缩放移动幅度、不挪动基线**（围绕 s0/s1 的中点收放）：
1 是完整行程，0.9（讲解版）推拉与位移都只剩九成，0 完全静止。
改这一个数就能整片调性——讲解版调 0.9，因为每镜要塞两行字，画面得让位。
结果始终落在 `[s0, s1]` 内，所以收幅度不会露黑边。

## 5. 转场

全片只有一种交叉溶解，会让每一次剪切的心理重量完全一样，观众读不出
"这一段完了、下一段开始"。**句子之间该有轻重**，所以转场写在**进入这个
镜头的**那一刀上（`shot 0` 没有转场，它是全片第一帧）：

| transition | 效果 | 适合 |
| --- | --- | --- |
| `crossfade` | 交叉溶解（`crossfade_frames`，默认 14） | 同一口气里的两句，别打断 |
| `dip-black` | 谷底正好落在剪切帧上，12+17 帧 | 情绪断裂处、终章收束 |
| `flash-warm` | 峰值迟到 5 帧的暖光，screen 混合 | 宣言句、由悲转豪 |
| `push-through` | 新镜从放大位落回本位（封顶 1.42） | 把观众推进新空间（扎进黄河） |
| `light-leak` | 暖光从侧边渗进来 | 段落转调、光起的那一刻 |

三种覆盖层（`dip-black` / `flash-warm` / `light-leak`）做成独立图层挂在
镜头交界处，**不动图像的 Sequence 结构**——镜头边界是钉在人声静默中点上的，
不能被转场改动。它们挂在字幕**之下**，压黑和闪白不会连字幕一起吞掉。

`push-through` 是唯一必须改图像本身的：它给新镜头一个入场额外放大，
在 20 帧内衰减。**它必须几乎硬切（5 帧压满，而不是 14 帧溶解）**——
1.4 倍放大配上 14 帧溶解，会得到两个不同比例的人物各半透明地叠在一起，
像印刷套版没对准，而不是"镜头扎进去"。

分法不是均匀发牌。参考编排（见 demo 的 plan）：

```text
0→1 push-through  片头一头扎进黄河，全片最重的一刀
1→2 dip-black     黄河之阔 → 明镜之悲，第一次情绪断裂
2→3 flash-warm    由悲转豪，「天生我材必有用」需要一记光
3→4 crossfade     同属豪放段落，这口气不能断
4→5 light-leak    歌起，暖光从侧边渗进来
5→6 crossfade     同段落
6→7 dip-black     历史苍凉收进破晓，沉下去作结
```

## 6. 画面内部动态层（fx）

运镜只能让整幅画平移缩放，观众很快会把它归成"背景在动，内容没动"。
真正把静图点活的是**画面里自己会动的东西**。

五个预设，名字按"空气里飘的是什么"取，而不是按强度取：

| fx | 内容 | 适合 |
| --- | --- | --- |
| `dust` | 浮尘（0.52）+ 轻雾 + 光扫 | 室内、堂上、有光的尘埃 |
| `mist` | 水汽（0.88）主导 | 黄河、河谷、水面 |
| `snow` | 飞雪（0.92，`normal` 混合） | 破晓、雪意、苍老 |
| `ember` | 火星（0.74）+ 强光扫 + 强呼吸 | 火、宴饮、豪气 |
| `quiet` | 全部压到最低 | 片头字卡底、需要绝对静的镜头 |

也可以逐镜写对象覆盖任意一项：`"fx": {"motes": 0.7, "haze": 0.2, "moteColor": "#e6e2d6"}`。

四个组件：

- **`Motes` 浮尘 / 飞雪 / 火星** — 8–38 颗，**两层景深**（远的小、暗、慢；
  近的大、亮、快），`size/rise/alpha` 全按 depth 插值。景深差是"空气中的颗粒"
  和"屏幕上的脏点"之间唯一的区别。
- **`Haze` 雾气流** — 三层不同大小、不同速度的柔光团横向漂移，位置周期都错开，
  所以看不见循环。`screen` 叠，暗部几乎不受影响，只在中间调和高光处浮起来。
- **`LightSweep` 光扫** — 一条斜向柔光带在镜头前半程扫过一次，`soft-light` 混合。
  逐镜一次，多了就假。
- **`breatheAt` 明暗呼吸** — ±2.2% 的亮度脉动，周期 4.6–7s（按 seed 错开，
  几支镜头不会同频闪）。人眼对亮度变化比对位移敏感得多，这一层最省成本。

**全部走 CSS 渐变与确定性 PRNG，不用 SVG 滤镜。** feTurbulence +
feDisplacementMap 那种真位移每帧要几百毫秒，两千多帧的成片会被拖成半小时。

`FilmAir` 把浮尘层提到**顶层**、用全局帧号驱动，而不是塞进每个镜头里：
空气不该在每次剪切时被重置。尘埃从第一个镜头飘到最后一个镜头，
中间换的只是密度和颜色（剪切那十几帧里前后两镜的气层互相渗透）。
于是七次硬切读起来像同一个空间里的七个机位。

图层顺序是有用的顺序，别动：

```text
场景图（运镜 + 呼吸 + 光扫）
  → 雾          ← 必须在暗角之下，否则暗角压不住它、画面发灰
  → 暗角
  → 浮尘         ← 必须在暗角之上，否则片边的尘埃被压没
  → 转场覆盖层    ← 必须在字幕之下，不吞文字
  → 字卡 / 字幕
  → 胶片颗粒
```

## 7. 字幕

两种角色对应页面里就存在的两个文本层：

- **`verse` 原文**：64px 衬线、字距 0.08em、月白。是朗诵主体，要压得住画面。
- **`prose` 释义**：42px、字距 0.02em、88% 透明度。是解释，不与原文抢读。

三件事同时发生，缺一件就会回到"字直接贴上去"的塑料感：

1. **模糊入场** — `blur 6px → 0`，10 帧。中文笔画密，纯 fade 像贴纸，从虚到实才像显影。
2. **上浮入场** — 18px 位移，给眼睛一个来处。
3. **逐字点亮**（仅原文层）— 按字数把整句摊在自己的人声区间里，
   念到的字全额、还没念到的字 42% 透明度。这是口播片字幕的标准形态：
   字幕不再是一句标语，而是跟着声音长出来的一条线。

逐字实现细节，改的时候别踩：

- 整句 **84%** 的区间用来铺字，留 16% 给尾音——人声的最后一个字往往
  比 sidecar 的 `end` 早，铺满会让字幕拖着等声音。
- 逐字只改 `opacity`、**不改 `display`**。包了 `span` 若改成 `inline-block`，
  会多出一次换行机会，`text-wrap: balance` 的断行结果就和整句不一样了。
- 未念到部分 `DIM = 0.42` 是实测下限：试过 0.32，在黄河亮水面和破晓亮天空上
  后半句会糊进背景读不出来。观众需要能"预览"整句话，逐字要做的是
  **加一处高光**，不是**遮住其余的字**。

硬规则：

- **最长一句必须单行放下**。`maxWidth` 1740px 就是按 23 字 × 64 × 1.08 再放宽一档算的；
  《将进酒》收尾句「……与尔同销万古愁。」实测在 1660px 下拆出孤字「愁。」成行。
  再配 `text-wrap: balance` 兜底：真要拆行时也拆成均衡的两行，不拆出孤字。
- 出场 7 帧。淡得太慢，上一句还在画面上，观众会把两句一起读。
- **释义层刻意不给逐字**：那是一整句解释，逐字闪会逼着观众盯着找节奏，
  反而读不进去。切得干脆才是解释该有的样子。用 `caption_reveal: false` 可整片关闭。
- 句与句之间的静默期**没有字幕**——这是有意的呼吸，不是遗漏。

## 8. 命令

在 Skill 根目录执行：

```bash
python scripts/video.py probe                    # 渲染链路自检（node/ffmpeg/浏览器/依赖）
python scripts/video.py init  --workspace <dir>  # 从模板建 Remotion 工作区
python scripts/video.py build --plan <plan.json> # 生成帧级时间轴 + 拷贝素材
python scripts/video.py still --workspace <dir>  # 每镜头入场/中段静帧（out/qa/）
python scripts/video.py render --workspace <dir> # 整片渲染（out/<slug>.mp4）
python scripts/video.py frames --workspace <dir> --input out/<slug>.mp4   # 成片抽帧回看
python scripts/video.py run    --plan … --workspace …   # 上面五步一条龙
```

常用参数：

- `init --node-modules <已装好的 node_modules>` — 离线环境直接复制现成依赖，
  不联网；省略则跑 `npm install`。指向任何一个装过 `remotion@4` 的目录都行。
- `render --frames 0-299` — 只渲一段，调镜头时省时间。
- `still --frames 60,200,2100` — 指定验收帧号。
- `frames --at 2.0,6.7,30.0` — 按秒从成片抽帧。

时间轴产物两份：`src/timeline.generated.ts`（给 Remotion）与
`timeline.json`（给 QA 与终检核对）。`build` 同时把场景图拷进
`public/scenes/`、音轨拷进 `public/audio/`。

**`init` 只在 `timeline.generated.ts` 缺失时写占位。** 已构建的工作区不会被
打回占位时间轴（旧版会，然后必须记得补一次 `build`，是个很容易踩的坑）。
改了模板后重新 `init` 即可，`src/` 是整棵复制，新加的组件文件会自动同步——
旧版维护着一份硬编码文件清单，漏一个就像用一个半旧的模板渲染，报错很难看懂。

## 9. 验收

与页面的浏览器 QA 同等重要，节奏是"静帧 → 整片 → 抽帧回看"：

1. **静帧验收（最高频）**：`still` 默认给每个镜头的入场中与中段各一帧，
   逐张看构图、字幕换行、字卡可读性。
2. **整片渲染**，然后 `frames` 从**成片**抽帧回看——预览里没出现、
   渲染后才暴露的问题（颗粒过重、暗角吃掉主体）只有这一步能抓到。
3. 每镜头至少看三帧：入场中、动作峰值、落定后。
4. 交付前派一个干净上下文的 subagent 做独立终检，输入包含成片、
   关键帧、plan、timeline.json 与审美准则；制作者对自己的产出有确认偏差。

常见破相（都有实测出处）：

- 字幕孤字成行（`maxWidth` 不够 + 缺 `text-wrap: balance`）；
- 逐字点亮把未念到的字压得太暗，亮背景上后半句糊掉（`DIM` 不低于 0.42）；
- 片尾字卡「淡入后又淡出」只剩残影——EndCard 只做淡入、一直压到最后一帧，别加淡出；
- 片尾字卡压在破晓的高亮天空上读不清（EndCard 自带暗晕，别删）；
- `scale` 推出黑边——钳位按**当前帧** scale 算并留 12% 余量，
  别手动加大 `tx/ty`；push-through 的放大有 `MAX_ENTER_SCALE` 封顶，别拆；
- **拉镜头把主体切出画框**：`settle` / `pull-out` 的起点是整片最紧的裁切，
  居左人物 + 大远景的图（如《将进酒》终镜）在 1.31 下幞头会被切掉。
  峰值锁 1.26；加幅度前先拿远景图验。
- **push-through 用默认的 14 帧溶解 → 双重曝光**（两个不同比例的人物半透明叠在一起）。
  它必须几乎硬切（5 帧压满），改 `ScenePlane` 里的 `fadeIn` 时别退回 `crossfade`；
- 颗粒过重像雪花屏（`grain_opacity` 0.06–0.08 之间）；
- 交叉溶解超过 20 帧开始发腻；
- 字幕压在高亮前景上（VerseCaption 自带柔性暗晕，别删）；
- 气层和字幕抢注意力（`motion_gain` 调低、`fx` 换 `quiet`）；
- 整片"平铺"——先查这三处：`motion_gain` 是不是被调太低、
  镜头是否全落回 `breath`/`creep` 这类小动作、`fx` 是否清一色 `quiet`。

## 10. 确定性渲染铁律

禁 `Date.now()` / `Math.random()`。一切伪随机走固定种子（mulberry32，
seed 从镜头序号派生）。颗粒的逐帧抖动同样来自帧号派生的种子——
静止噪点像蒙了层脏屏幕，动起来才像胶片，而且两次渲染逐帧一致。

## 11. BGM / 音效扩展点

时间轴支持 `bgm`（`<Audio volume={bgmVolume}>`，默认 0.3）与
`audioVolume`。诗词语境默认**不配 BGM 不配音效**：人声是唯一的声音主角，
铺乐需要用户明确要求，并按 video-shotcraft 的 `music-beat-sync.md`
先做节奏分析再分镜。素材可用 video-shotcraft 仓库 `assets/audio/`
（免费商用授权，见其 ATTRIBUTION.md）。
