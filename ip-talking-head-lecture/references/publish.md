# 发布文案与字幕文件

`script.json` 里写一个 `publish` 段，`iph build` 就会生成 `<期>/发布文案.md` 和四个字幕文件。

```bash
iph build <期>      # 生成全部文稿（配音有缓存，秒级完成）
```

**不写 `publish` 段也能跑**——只是不出《发布文案.md》。字幕文件照常生成。

## 产物

| 文件 | 内容 |
|---|---|
| `发布文案.md` | 主用标题 + YouTube 双语板块 + 视频号 / 小红书 / 抖音 / 公众号 + 配套文件清单 |
| `字幕.srt` | 中文字幕（标准 SRT，剪映 / Aegisub 可用） |
| `字幕.vtt` | 中文 WebVTT（YouTube 更推荐） |
| `字幕.en.srt` | 英文字幕（需填 `publish.en.cues`） |
| `字幕.en.vtt` | 英文 WebVTT |

## publish 段结构

```jsonc
"publish": {
  "title": "主用标题（全平台通用）",
  "titles": ["备选标题 1", "备选标题 2"],

  "videoAccount": "视频号 / 朋友圈文案。多段之间用 \n\n 分隔",
  "xiaohongshu": "小红书文案（含 #话题）",
  "douyin": "抖音 / B 站文案。想插时间轴就写 {{chapters}}",
  "articleLead": "公众号导语",

  "tags": ["AI工具", "WorkBuddy"],
  "hashtags": "#AIVideo #AIGC",

  "youtube": { /* 见下 */ },
  "en":      { /* 见下 */ }
}
```

### 平台文案里的 `{{chapters}}`

写 `{{chapters}}` 的地方会被替换成**场景级**时间轴（逐分镜，不合并）：

```
0:00 一句话，做一条视频
0:08 三个角色，各管一段
...
```

好处是**永远和成片一致**——改一句旁白、重排时长，时间轴自动更新，不用手改。
写死的 `00:08` 这种时间戳会在改稿后悄悄过期，所以抖音 / B 站文案建议一律用占位符。

### `youtube` 子段

```jsonc
"youtube": {
  "title": "中文标题",
  "titleEn": "English title",
  "desc": "中文描述正文（不含章节，章节自动追加）",
  "descEn": "English description body",
  "tags": ["AI video", "Remotion"],
  "cta": "中文行动引导，追加在描述末尾",
  "ctaEn": "English call to action",
  "chapterMinSeconds": 10,
  "chapterTitles": ["章节名 1", "..."],
  "chapterTitlesEn": ["Chapter 1", "..."]
}
```

`chapterTitles` / `chapterTitlesEn` 与 `scenes` **一一对应**（按分镜序号），不给就直接用该分镜的 `heading`。

### `en` 子段（英文字幕）

```jsonc
"en": {
  "cues": ["English line 1", "English line 2", "..."]
}
```

**`cues` 必须与中文字幕条数完全一致**（不是分镜数，是字幕条数——`iph srt <期>` 可以看条数）。
条数对不上时 build 会**跳过英文字幕并打印警告**，宁可不出也不错位。

## YouTube 章节的硬性要求

YouTube 认章节的条件（任一条不满足，**整组章节会被忽略**）：

1. 第一条必须是 `0:00`
2. 至少 3 条
3. **每章至少 10 秒**

第 3 条最容易踩。60 秒 6 分镜的片子，单个分镜往往只有 8~9 秒 —— 直接按分镜写章节会被 YouTube 全部丢弃。

所以 `lib/publish.mjs` 的 `groupChapters()` 会**自动把不足 10 秒的分镜并进当前章节**，直到够长才开新章；末尾剩的短章节并进上一章。

因此《发布文案.md》里会出现两个时间轴，**条数不同是正常的**：

| 位置 | 粒度 | 用途 |
|---|---|---|
| YouTube 区块 | 合并后（每章 ≥10s） | 贴进 YouTube 描述，能生效 |
| 抖音 / B 站等（`{{chapters}}`） | 场景级（不合并） | 只是看点导航，无长度限制 |

合并后的章节名取**组内第一个分镜**的标题。想精确控制就写 `chapterTitles` / `chapterTitlesEn`。

## 英文字幕怎么对齐

英文字幕**复用中文字幕的时间轴**，逐条替换文本 —— 这是标准做法：

- 一条中文对应一条英文，时间码完全相同
- 因为中文的断句已经按 TTS 的停顿切好了，英文沿用这套边界，读起来节奏一致
- 翻译时**按条翻译**，不要跨条重组句子（一条英文太长就在条内用逗号展开）

YouTube 上传时：

1. 进「字幕」页 → 添加语言 → **中文（简体）** → 上传 `字幕.vtt`
2. 再加一门 → **英语** → 上传 `字幕.en.vtt`
3. 两份共用一条时间轴，不会有偏移

`字幕.en.srt` 是同一内容的 SRT 版，剪映 / 其他平台只吃 SRT 时用。

## 平台文案的写法口径

| 平台 | 长度 | 口径 |
|---|---|---|
| 主用标题 | ≤ 30 字 | 一句话说清"这是什么 + 有什么用"，别用疑问句开头 |
| 视频号 / 朋友圈 | 150~250 字 | 像跟朋友讲一件事，最后留个"下一期"的钩子 |
| 小红书 | 300~500 字 | 前面加粗一句钩子，中间用 1/2/3 编号，结尾堆 #话题 |
| 抖音 / B 站 | 80~150 字 | 方括号里放一句话介绍，正文短，末尾放时间轴 |
| 公众号导语 | 100~200 字 | 从"痛点"切入，交代这一期讲什么、结尾有什么 |
| YouTube 描述 | 300~600 字 | **前 3 行是搜索与推荐的主力**；正文 → 章节 → CTA → hashtag |

## 常见问题

| 症状 | 原因 |
|---|---|
| 没有生成《发布文案.md》 | `script.json` 没写 `publish` 段 |
| 警告 `publish.en.cues 有 N 条，但中文字幕是 M 条` | 条数不匹配，英文字幕被跳过。用 `iph srt <期>` 数一下中文条数 |
| 英文字幕里的章节标题是中文 | `youtube.chapterTitlesEn` 没填，退化成用了分镜 `heading` |
| 提示"分镜不足以凑出 3 个 ≥10 秒的章节" | 片子太短（总长 <30 秒）。YouTube 章节功能用不上，描述里别放时间戳 |
| `{{chapters}}` 原样出现在文案里 | 拼写错了（大小写敏感，是两个花括号） |
