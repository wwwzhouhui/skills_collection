# 演示型文章排版模式（工具教程 / 案例演示）

适用于「AI 工具教程 + 实战演示」体裁的公众号文章：通篇是一个工具体验的完整演示，穿插可复制的提示词块、案例过程和作者判断。样本见 [examples/remotion-demo.md](../examples/remotion-demo.md)（WorkBuddy + Remotion 上手指南，本文所有规则都在该样例中落地）。

## 结构模式：六段式演示骨架

这类文章几乎总是同一副骨架，改写时按此顺序排：

| 段落 | 作用 | kicker / 容器 |
|---|---|---|
| 痛点开场 | 具体职业场景 + 一个尴尬需求，一段内让读者对号入座 | `TOPIC` 或 `INTRO` |
| 是什么 | 一两段讲清工具定义 + 与相邻方案的边界（不适合什么） | 纯数字 `01` |
| 上手路径 | 安装、授权、第一句提示词、预览与导出 | 纯数字 `02`，配套 `InfoCard` 放前置条件 |
| 案例演示 ×N | 每个案例：需求描述 → 交给 Agent 的提示词 → 效果描述 | 纯数字 `03`/`04`/`05`，提示词走代码块 |
| 感性收尾 | 门槛降低的感慨 + 一句态度 | `07`/`OUTRO`，金句走 `>` 引用 |
| 带走清单 | 3-4 条可执行结论 | `SummaryCard` |

**章节 kicker 一律用纯数字 `01/02/03`**（不用 `STEP`）——这类文章的节是并列的案例与主题，不是"先做 A 再做 B"的严格顺序。全文起手用 `TOPIC`。

## 风格模式

### 1. 提示词块：`●●●` 标记 → 代码块

原文章用 `●●●` 分隔线标记"下面这段话可以直接发给 Agent"。排版时：

- 整段原样收进 ``` 代码块（保留引号、空行、编号，一个字不改）
- 代码块前一句引语说明用途，如"然后把下面这段话发给它："
- 代码块后跟一小段"Agent 的真实反应"（它做了什么、花了多久），这是演示感的来源

### 2. 参数步骤：短步骤 → 有序列表 + 加粗

导出参数、渲染四步这类内容，用 `1. 2. 3.` 有序列表，关键词加粗（`**ProRes**`、`**4444 XQ**`），不要写成大段流水文字。

### 3. 判断句 → 引用块

作者的态度和判断（"强的只是工具不是你"）拆成 `>` 引用块，独立成立、15-40 字。

### 4. 颜色与方案映射

演示型工具文多配有绿色/深色视觉。映射到内置 scheme：

- 主色为深绿/翠绿系（样本源文 #255E4A + #F1F4F3，编号徽章 + 终端提示词窗口）→ **`forest-demo`**（森绿演示）。不要再映射到 `jade-business`
- 主色为高对比黑白/荧光点缀 → `mono-tech`
- 全深色背景 → `midnight-report`

### 5. 视频/演示位

本 skill 的渲染器只支持公网 URL 图片（`![alt](url)`），不支持视频嵌入。原文章中的视频演示位处理为二选一：

- 有公网封面图 → `![案例演示](公网URL)`
- 无图 → 用一句话文字描述效果（"成片效果很不错：字幕包装到位，动效精致"），不要留「视频加载失败」这类占位残片

## 改写示例（before → after）

**before（原文章片段）：**

```markdown
于是只需要跟agent提需求说：保留现在的版本，再给我一个透明背景格式的版本。
要去掉背景就得导出带透明通道的视频。把视频编码改为ProRes，
ProRes profile这里，选择第一个 4444 XQ，图片格式改为PNG，
像素格式，选择最后一个yuva444p10le，最后点击Render video。
```

**after（示范排版）：**

```markdown
于是只需要跟 Agent 提需求说：保留现在的版本，再给我一个透明背景格式的版本。不一会儿，合成列表里就多了一个新的视频合成，它是去掉背景的版本。

要去掉背景，就得导出带透明通道的视频，四步完成：

1. 视频编码改为 **ProRes**
2. ProRes profile 选择第一个 **4444 XQ**
3. 图片格式改为 **PNG**
4. 像素格式选择最后一个 **yuva444p10le**

最后点击 Render video，就可以渲染视频了。导出之后，就可以把这个透明背景的动画素材叠加到自己任意视频中。
```

改动只有三处：长句拆成"引导句 + 有序列表"、参数加粗、补一句用途收尾——没有新增任何观点。

## 自检

- [ ] 开场是否两段内出现了具体职业场景和尴尬需求？
- [ ] 每个案例是否都有「提示词块 → Agent 反应」两件套？
- [ ] 提示词是否一个字未改、且用了代码块？
- [ ] 章节 kicker 是否全篇统一为纯数字（或全 `CASE`），没有 STEP/CASE 混用？
- [ ] 结尾是否有金句引用 + SummaryCard，且卡片条目原文都有出处？
