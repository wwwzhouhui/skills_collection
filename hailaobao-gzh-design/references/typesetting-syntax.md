# 扩展 Markdown 语法

标准 Markdown 支持全部标记（`**bold**`、`*italic*`、`` `code` ``、` ```block``` `、`- list`、`> quote`、`---`、`![img](url)`、`[link](url)`）**加上**下面的公众号专用扩展。

**渲染器只识别下面列出的扩展，未列出的自定义组件会被当作普通段落。**

---

## 1. 标题的 `|` 高级语法

用竖线分节，让标题在公众号里看起来像编辑部的开篇。

```markdown
# 01 | 主标题 | 小字副标题
## STEP 02 | 主标题
### 序号或标签 | 小节标题
#### 段落小标题
```

规则：
- **一级 `#`**：`序号 | 主标题 | 小字副标题`（副标题可省）
- **二级 `##`**：`序号标签 | 主标题`（序号标签可省，形如 `STEP 01` / `01` / `CASE 02` / `PART A`）
- **三级 `###`**：`标签 | 小节标题`（标签可省）
- **四级 `####`**：普通段落小标题，不用竖线

**序号 / 标签**尽量用大写英文或数字，视觉上有编辑部感。

**kicker 的选用要匹配段落语义**——完整决策表见 [formatting-rules.md](formatting-rules.md#关键kicker-类型必须匹配段落语义不能全篇甩-step)。速查：

| 段落语义 | kicker |
|---|---|
| 顺序动作 / 教程步骤 | `STEP 01` |
| 并列机会 / 方向 / 要点清单 | 纯数字 `01` / `02` |
| 案例 / 举例 | `CASE 01` |
| 大板块 / 章节 | `PART A` |
| 问答 | `Q1` / `A1` |
| 误区 / 警示 | `AVOID 01` |
| 原则 / 铁律 | `RULE 01` |
| 技巧 / 小妙招 | `TIP 01` |
| 数据 / 事实 | `FACT 01` |
| 起手 / 收束 | `TOPIC` / `INTRO` / `OUTRO` |
| 拿不准 | **纯数字 `01/02/03` 永远兜底** |

**同类段落用同一 kicker**，不要一篇里前 5 个 `STEP` 后 5 个 `CASE`（除非段落性质真的变了）。

---

## 2. 局部彩色文字

在标题或段落里嵌 `<span>` 加颜色：

```markdown
## STEP 02 | <span style="color:#059669">深度解析</span>
```

只允许 `color` 一个 CSS 属性，别的 CSS 会被过滤。

颜色必须 `#RRGGBB` 6 位十六进制。

---

## 3. 总结卡片 `<SummaryCard>`

段落级组件，通常放在文章末尾或章节末尾做**收束**。

```markdown
<SummaryCard title="核心要点">
- 第一条要点
- 第二条要点
- 第三条要点
</SummaryCard>
```

- `title` 属性：≤10 个汉字的短标题
- 内部支持普通 Markdown（列表、加粗）
- 一篇文章最多 1-2 张，不要滥用

---

## 4. 信息卡片 `<InfoCard>`

段落级组件，用来**提示、警告、小贴士、注释**。

```markdown
<InfoCard title="提示">
如果你使用的是 macOS，需要先安装 Xcode Command Line Tools。
</InfoCard>
```

- `title` 属性：≤8 个汉字
- 一段话即可，不要塞列表和大段代码

---

## 5. 分割线 `---`

标准 Markdown。渲染出小的横线 + 装饰点，用于**章节切分**。

规则：
- 一级标题之间**必须**放一根
- 段落之间**不需要**用它当空行；行距靠段落之间的空行自然产生
- 相邻两根 `---` 之间要有实际内容，别拿它当装饰堆

---

## 6. 图片

标准 Markdown `![alt](url)` 即可。渲染时按 scheme 的圆角 / 阴影包一层。

**不支持**图片本地路径 —— 必须是可公开访问的 URL。作者应先把图上传到自己的图床再引用。

---

## 7. 代码块

标准三重反引号。语言标签用于配色。

支持：`js`、`ts`、`tsx`、`jsx`、`py`、`sh`、`bash`、`json`、`yaml`、`html`、`css`、`sql`、`go`、`rust`、`java`、`kotlin`、`swift`。

代码块的样式由 scheme 决定（终端 / 印刷 / 直角）。

---

## 8. 不支持的语法（改写时不要用）

- HTML `<table>` — 公众号编辑器兼容差，用列表替代
- HTML `<iframe>` — 公众号不允许外链
- 数学公式 `$$...$$` — 公众号不解析
- 脚注 `[^1]` — 渲染器不识别，会当普通文本
- 任意其他 HTML 标签（`<div>`、`<section>` 等）都不会正确处理，坚持用 Markdown + 上面 4 种扩展
