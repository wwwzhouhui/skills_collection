# 安全边界与恢复说明

## 三平台共同原则

WorkBuddy 数据目录可能包含会话、数据库及 WAL/SHM、项目、配置、插件和身份材料。迁移只改变数据的物理位置和原路径入口，不改变应用协议、数据库结构或登录状态。

所有平台都遵守：

1. 先只读检查，再取得本次明确确认。
2. 应用完全退出后才复制；脚本复查进程，但不强杀。
3. 复制后做全量 SHA-256 清单比对，源与目标都通过才切换。
4. 原目录只改名保留，不递归删除；目标目录永不自动删除。
5. 不读取、展示或上传文件正文、令牌和数据库内容。
6. 不自动清理旧备份，不自动提权，不修改系统安全策略。

## 迁移记录与状态机

每次实际迁移在源同级创建 `<源路径>.backup-<标识>` 和 `<备份路径>.migration.json`。状态文件只记录路径、文件相对清单、大小、文件权限位和 SHA-256，不含文件正文；路径本身可能敏感，状态文件权限设为仅当前用户可读写（POSIX `0600`，Windows 收紧 ACL）。

| 状态 | 含义 | 最小恢复动作 |
|---|---|---|
| `Copying` | 正在复制或复制未通过 | 源应保持原状。检查源入口与目标，不自动清空目标重试。 |
| `Verified` | 内容校验通过，切换尚未记为完成 | 检查源、备份和入口的实际结构；中断可能发生在改名与建链之间，不能仅凭记录判断。 |
| `Linked` | 入口校验及状态记录完成 | 应用验收待用户完成，可用 Rollback。 |
| `RolledBack` | 原备份已恢复，目标仍保留 | 目标可能含较新的状态，不能当作废弃缓存删除。 |

掉电或异常退出可能使状态记录落后于实际目录结构。自动回滚只接受完整 `Linked` 状态，不猜测修复。先只读检查，再确认对应动作：

1. 应用完全退出。
2. 原入口不存在、备份是普通目录：核实本轮路径后，可把备份恢复原名；目标保留。不得覆盖已重新出现的源目录。
3. 原入口是本轮链接：先核验备份和目标内容，处理新写入后，才可移除入口并恢复备份。
4. 路径或类型不匹配：停止，不删除、不合并数据库、不猜测目标。

## 回滚与新数据

回滚返回的是迁移前状态，不是把目标盘最新数据同步回原盘。脚本会检查备份未被改动，并比较目标与迁移时的内容清单。

- 目标无变化：允许回滚。
- 目标有新增、删除或修改：默认拒绝。用户明确接受“旧状态恢复，新状态仍保存在目标但暂不活跃”后，Windows 加 `-AcceptNewDataInTarget`，Linux/macOS 加 `--accept-new-data-in-target`。
- 不自动合并数据库、不覆盖新文件、不改数据库结构。

POSIX 脚本只对经核验的符号链接调用 `os.unlink`，不带递归；Windows 脚本只对经核验的 junction 调用 `[IO.Directory]::Delete(path)`，不带递归。两者都不能改成递归删除或删除目标。

## 释放空间

备份默认位于源旁边，因此切换后新的写入进入目标盘，旧数据仍占原盘空间。不要报告“已释放全部空间”。

只有同时满足以下条件才处理旧备份：

1. 用户已完成应用验收。
2. 用户确认有可靠的非系统盘恢复副本。
3. 用户单独批准删除这一轮旧备份，并确认精确路径。

删除前重新检查该路径是普通目录且不是活跃入口。不要递归删除链接，不要按通配符批量删除。旧备份删除后，原地回滚不再可用。

## 支持范围与限制

### Windows

- Windows PowerShell 5.1、系统 robocopy、本地固定 NTFS 目标盘，当前 Windows 用户。
- 不需要默认管理员身份；权限不足则停止，不修改系统执行策略。
- 不处理源或祖先/内部 reparse point、Windows 保留设备名、超长路径、网络盘/移动盘、非空目标、系统盘目标。
- 目标 ACL 会被收紧；复制使用 DAT 而不是源的完整 ACL。
- 本脚本沿用参考实现，其逻辑在本技能构建环境中未用 PowerShell 5.1 / robocopy 实机执行验证；首次使用前先运行 `-Action Inspect` 核对路径、空间与进程。

### Linux / macOS

- Python 3.8+ 标准库；源目录名必须为 `.workbuddy` 或 `WorkBuddy`。
- 入口使用符号链接。要求 WorkBuddy 在读取原路径时跟随符号链接；脚本无法替应用做这项兼容性保证，必须通过应用验收确认。
- 源内部出现符号链接、socket、FIFO 或设备文件时停止，不静默跳过、不跟随、不复制。
- 路径祖先含符号链接（例如 home 本身是链接）时默认拒绝；确认布局后可用 `--accept-symlinked-ancestors` 显式接受。
- 目标必须为空、不与源嵌套、不位于系统目录，父目录必须存在且可写。
- 目标空间需大于数据量加 256 MiB 余量。
- 复制保留文件权限位与时间戳（尽力而为），不保证 ACL、扩展属性或 macOS 资源分支完整；应用验收必须覆盖这些依赖。
- macOS 受系统隐私保护（TCC）或权限限制的目录可能拒绝访问，脚本会停止并保留原数据。
- 全文件 SHA-256 会增加读取耗时；Inspect 只统计元数据，运行中的数据大小只是瞬时快照。
- 全量清单驻留内存，迁移期会进行 3 次全量读取。文件数达到十万级或数据量很大时，预留更长的维护窗口并确保足够内存和两份空间；本工具未实现分批或增量校验。
- 本实现使用 POSIX 标准库并附带 `scripts/selftest_posix.py`。Linux 构建环境已完成端到端自检；macOS 与 Linux API 一致但未在本次构建环境实机验证，请在 macOS 目标机上先运行自检再迁移真实数据。

### 共同不保证

- 进程检查不能替代用户主动关闭应用；复制或回滚期间不要重新启动 WorkBuddy。
- 应用自启、插件或其他写入者不属于强制锁定保证。
- 不保证原盘上所有 WorkBuddy 相关目录都停止增长；日志、更新缓存等可能在别处。
- 本工具不是跨机器登录迁移工具。
