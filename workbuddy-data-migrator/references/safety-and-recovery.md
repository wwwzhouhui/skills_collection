# 安全边界与恢复说明

## 参考依据

参考用户提供的《WorkBuddy-C盘爆红排查与无损搬家（文章整理）》：安装目录与用户数据目录不是同一位置；Windows 目录联接可以保留旧入口，让应用继续使用原路径。

本工具不照搬以下建议：

- 不直接剪切三个目录。当前仅处理 `.workbuddy`，先复制且校验完整内容。
- 不默认 `.workbuddy-key-fallback` 是目录，不额外迁移它。此方案不是跨机器登录迁移工具。
- 不粉碎 `nul` 或其他名称异常的文件。脚本停止，保留原数据，等待单独处理。
- 不把“显示创建联接”或资源管理器小箭头当作完整验证。
- 不认为改工作空间就一定迁走全部用户状态；不把卸载重装称为可靠的无损替代。

## 迁移记录与失败恢复

每次实际迁移会在源同级创建 `<源路径>.backup-<标识>.migration.json`。包含路径、文件相对清单、大小和 SHA-256，不包含文件正文，但路径仍可能敏感；记录仅当前用户及系统/管理员可读写。

| 状态 | 含义 | 最小恢复动作 |
|---|---|---|
| `Copying` | 尚在复制或复制未通过 | 源应保持原状。检查源入口与目标，不自动清空目标重试。 |
| `Verified` | 内容校验通过，切换尚未记为完成 | 检查源、备份和 junction 的实际情况；中断可能发生在改名与联接之间，不能仅凭记录判断。 |
| `Linked` | junction 校验及状态记录完成 | 应用验收待用户完成，可用 Rollback。 |
| `RolledBack` | 原备份已恢复，目标仍保留 | 目标可能含较新的状态，不能当作废弃缓存删除。 |

掉电或异常退出可能使状态记录落后于实际目录结构。自动 Rollback 只接受完整 `Linked` 状态，不猜测修复。先只读检查，再确认对应修复动作：

1. WorkBuddy 完全退出。
2. 源入口不存在、备份是普通目录：核实本轮路径后，可将备份恢复原名；目标保留。不得覆盖一个已重新出现的源目录。
3. 源入口是指向本轮目标的 junction：先核验备份和目标内容，处理新写入后，才可移除入口并恢复备份。
4. 路径或类型不匹配：停止，不删除、不合并数据库、不猜测目标。

## 新数据与回滚

回滚返回的是迁移前状态，不是将外盘最新数据同步回 C 盘。脚本会检查备份没被改动，并比较目标与迁移时的内容哈希。目标有变化时默认拒绝；用户明确接受“旧状态恢复，新状态仍保存在目标但暂不活跃”后，才使用 `-AcceptNewDataInTarget`。

脚本只对验证通过的 junction 调用 `[IO.Directory]::Delete(path)`，不带递归参数。不能改为 `Remove-Item -Recurse`、`rd /s` 或删除目标。它随后恢复备份原名，记录结果，目标始终保留。

## C 盘释放空间

默认备份位于源旁边。因此切换后新的写入在目标盘，旧数据仍占 C 盘。不要报告“已释放全部空间”。只有用户完成应用验收、确认有可靠的非系统盘恢复副本并单独批准删除这轮旧备份，才处理释放空间。

迁移记录需保留至验收和清理决定完成。旧备份被删除后，本工具的原地 Rollback 就不再可用，应从用户保留的外盘备份恢复。

## 支持范围

- Windows PowerShell 5.1、系统 robocopy、本地固定 NTFS 目标盘，当前 Windows 用户。
- 不需要默认管理员身份，不更改系统执行策略；权限不足则停止。
- 不处理源或祖先/内部 reparse point、Windows 保留设备名、Win32 长路径、网络盘/移动盘、目标非空、系统盘目标。
- 全文件 SHA-256 会增加读取耗时；预检仅计算元数据，运行中的数据大小只是瞬时快照。
- 目标目录 ACL 会被收紧；复制使用 DAT 而不是复制源的完整 ACL。新建文件继承目标私有权限。源目录和源权限不修改，直到成功校验后的改名切换。
- 进程检查不能替代用户关闭应用；请不要在复制或回滚中重新启动 WorkBuddy。程序自启或其他写入者不属于强制锁定保证。
- 本工具不保证 C 盘所有 WorkBuddy 相关目录都停止增长，不改鉴权协议、数据库结构或应用配置。
