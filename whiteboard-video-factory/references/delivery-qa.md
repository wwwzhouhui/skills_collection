# 成片验收与交付边界

`wb build` 出片之后、交付之前的最后一道关。机器检查与目视抽帧都要做，只写实际做过的。

## 机器检查（必做）

```bash
ffprobe -v error -show_entries format=duration:stream=index,codec_type,codec_name,width,height,r_frame_rate,duration -of json final.mp4
ffmpeg -v error -i final.mp4 -f null -
```

- 尺寸 1920×1080、fps 30、总时长、音轨存在且非静音；视频与音频结束对齐（允许一帧量化误差）。
- 字幕区间有序、不重叠；每句确认正文都有音频和画面；尾句说完再压黑。
- 黑帧检测后人工判断，深色品牌底不等于黑帧；无黑帧也不证明视频层正常。
- **时长以 `ffprobe` 为准**写进期目录 `README.md`，不用接口估时。

## 目视抽帧（必做）

- 首、中、尾各一帧，外加每处结构变化（场景切换、贴纸入场、片尾卡）。
- 看：字幕在底部安全区、水印在右上、无越界遮挡、贴纸擦出边缘正常。
- 看 `字幕.srt` 前几条：原文拼写正确、数字没被拆开。
- **跟读高亮**（`config.json` 的 `captions.highlight.enabled` 为真时）：抽帧要挑"某句正念到一半"的时刻，看色块紧贴当前那几个字、被高亮的字转成纸色、标点没被吞进色块、`MiMo` 这类英文词没被拦腰截断。不打图也能先核对：`wb captions <期>` 会打印每段切分（`[a·b·c]` 里 `·` 就是色块跳的节拍，每段约 0.2~0.6 秒算正常）。高亮只烧进画面，`字幕.srt` 里没有。
- 逐笔描边、铅笔跟随这类运动镜头要连续播放或看相邻帧，单帧不能证明平稳；没有逐秒听审就如实写"未完成"。

## 封面验收（三张都要看）

- `wb cover` 出的 4:3 / 3:4 / 9:16 逐张打开看：文字没撞贴纸、高亮压在钩子行、品牌标在角上。
- 9:16 是抖音封面：关键内容要落在**中央安全区**，因为抖音封面上下会被裁掉一部分（1080×1920 实际展示约 1080×1464）。
- 把封面缩到 240~320px 看主标题还能不能读——信息流里就是这个尺寸。
- 封面文案与 `发布.md` 同版本，数字与期目录 `README.md` 一致。

## 交付边界

- 只宣称实际完成的检查；QA 结论分开写机器检查、目视检查、未完成项。
- 路径指向可播放的**新**成片（`<dirs.build>/<期>/outputs/final.mp4`）；存在旧 MP4 不代表新版本已合成，`final / v3 / 完整版` 文件名不代表状态。
- **已制作 ≠ 已发布。** 制作授权不含公开发布，用户验收材料不等于已上线；本流程只备稿，不发评论、不公开发布、不改账号设置。
- 改稿后旧导出冻结，需重出片并更新期目录入口；不覆盖用户源素材和已交付成片。
