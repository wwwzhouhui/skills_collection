# 文章封面生成器

把一篇文章的标题和内容变成一张指定比例的 AI 封面图。默认使用 `gpt-image-2.5`，也可选择魔搭社区 ModelScope 的 `MiniMax/MiniMax-H3-Image`。

## 工作流程

### 第 1 步：确认输入

需要确认以下内容，缺少标题时先向用户询问：

1. **文章标题**（必需）— 用户直接给出，或从文章文件第一行/文件名提取。
2. **文章内容**（可选但强烈建议）— 用于提炼画面元素。可以是文件路径（读文件）或内联文字。只有标题也能生成，但画面元素会偏泛。
3. **比例** — 用户没指定就默认 `4:3`，并在结果里说明用了什么比例、支持哪些（16:9、9:16、3:4、4:3、1:1），方便用户换比例重跑。
4. **模型** — 用户点名时按其选择；没指定就使用 `gpt-image-2.5`。可选：
   - `gpt-image-2.5`：第三方中转站，使用 size 参数控制比例。
   - `MiniMax/MiniMax-H3-Image`：魔搭社区 ModelScope，当前接口只按提示词约束构图比例，最终比例以实际图片为准。

### 第 2 步：从文章提炼画面元素

通读文章，回答三个问题（不需要写给用户看，直接进入提示词）：

- 文章**核心主题**是什么？（如：AI 语音克隆、低代码部署、开源工具实测）
- 文章里有哪些**具体视觉符号**？（如：麦克风、声波、AI 机器人、代码编辑器窗口、GitHub 卡片、云部署图标、聊天气泡）挑 2~4 个最核心的，不要堆砌。
- 有没有**流程感/对比感**？（如“提示词→生成→上线”的三段式）有就体现为画面中的元素流转。

### 第 3 步：写图片提示词

**用中文写**，按下述模板组装（这是已验证出好图的结构，字段顺序保持不变）：

```text
现代科技感扁平插画风格的技术文章封面，浅蓝到淡紫渐变背景，明亮干净。画面中央是<核心视觉符号1>和<核心视觉符号2>，<两者之间发生的动作/关联>；周围漂浮<文章相关的UI卡片，如代码编辑器窗口、部署状态卡片>。顶部横幅区域写大标题《<文章标题>》，下方小字副标题“<从标题拆出的短副标题，10字内，可省略>”。科技蓝为主色，橙色点缀，<横版/竖版> <比例> 构图，细节丰富，高清
```

写作规则：

- **标题必须原文照抄进提示词**，用《》括起来——这是封面的核心信息。不同模型的中文文字准确率会波动，交付前必须预览核对，不能仅凭任务成功就宣称标题无误。
- 副标题只在主标题偏短时加，10 字以内；小字（代码注释、卡片细节）容易糊，**不要**要求生成成段文字。
- 视觉符号要具体（“发光的麦克风、向外扩散的声波光带”），不要抽象（“科技的感觉”）。
- 末尾的构图方向词和比例要写（如“横版 16:9 构图”）。GPT 路径会同时传 size；ModelScope 路径会由脚本再次补充比例要求。
- 用户的原始描述里如果给了风格要求（如“极简海报风”），覆盖模板默认风格。

### 第 4 步：调用脚本生成

脚本一次性完成：选择模型 → 创建任务 → 轮询 → 下载到本地 → 检测图片格式与尺寸。**不要**自己手搓 curl 分步调用。

默认 GPT 模型：

```bash
node "<本技能目录>/scripts/gen_cover.mjs" --prompt-file <提示词临时文件> --ratio 16:9 --out <输出路径.png>
```

选择 MiniMax-H3-Image：

```bash
node "<本技能目录>/scripts/gen_cover.mjs" --model MiniMax/MiniMax-H3-Image --prompt-file <提示词临时文件> --ratio 16:9 --out <输出路径.png>
```

- `--model`：推荐值为 `gpt-image-2.5` / `MiniMax/MiniMax-H3-Image`；命令行优先于 `.env` 的模型配置，默认前者。为兼容旧版，其他自定义模型名继续发送到 GPT 兼容网关。
- `--prompt-file`（推荐）：中文长提示词经命令行传参在 Windows 下有编码风险，先 Write 成 UTF-8 临时文件；也支持 `--prompt "..."`。
- `--ratio`：`16:9` / `9:16` / `3:4` / `4:3` / `1:1`，默认 `4:3`。
- `--size`：仅 GPT 路径支持，用于直接指定像素；MiniMax 的 ModelScope 托管接口未确认支持该参数，选择 MiniMax 时只能使用 `--ratio`。
- `--out`：完整输出路径。默认存当前工作目录，命名建议 `封面_<比例>_<标题slug>.png`；用户给了文章文件路径时，默认存到文章同目录。

首次使用把 `.env.example` 复制为技能根目录 `.env`，只填写所选模型对应的密钥：

- GPT：`ARTICLE_COVER_API_KEY` 必填，`ARTICLE_COVER_API_BASE` 可选。
- MiniMax：`ARTICLE_COVER_MODELSCOPE_API_KEY` 必填，`ARTICLE_COVER_MODELSCOPE_API_BASE` 可选。
- 模型缺省为 `gpt-image-2.5`；也可用 `ARTICLE_COVER_MODEL` 设置技能默认模型。除精确的 `MiniMax/MiniMax-H3-Image` 外，旧版自定义模型名继续走 GPT 兼容网关。

脚本也接受 `ARTICLE_COVER_*` 进程环境变量；技能目录 `.env` 兼容旧配置名 `MODEL` / `API_BASE` / `API_KEY` / `MODELSCOPE_API_BASE` / `MODELSCOPE_API_KEY`。命令行模型优先，其次是进程 `ARTICLE_COVER_MODEL`，再读取 `.env`；进程环境不读取通用旧名，避免与其他程序碰撞。同一服务的 BASE 与 KEY 必须来自同一配置来源，避免本地密钥被发往进程中的意外端点。密钥只能进入忽略提交的本地 `.env` 或当前进程环境；不要写进脚本、提示词、测试、文档、日志或命令示例。用户若曾在对话中明文提供 Token，验证后提醒其在服务后台轮换。

成功时脚本输出最后一行 JSON，例如：

```json
{"ok":true,"path":"...","format":"png","width":1280,"height":720,"ratio":"16:9","task_id":"...","provider":"modelscope","model":"MiniMax/MiniMax-H3-Image"}
```

### 第 5 步：交付

1. 用 Read 打开生成的图片给用户预览，核对标题文字、构图和比例。
2. 报告：所用模型、本地文件路径、实际尺寸、请求比例。提醒：远程图片 URL 可能过期，本地文件才是持久副本。
3. 用户不满意时，先问清不满意的是构图、文字还是配色，改提示词对应部分再重跑。每次重跑都是一次新的计费生成，必须先获得用户同意，不能擅自连环重试。

## 失败处理

- 内容审核类失败 → 调整提示词里的敏感表述，**先向用户说明并取得同意再重新生成**。
- 创建请求发生网络错误 → 服务端可能已经接收任务，脚本不会自动二次提交，错误也会标记为不可安全重试；报告错误，不要自行重跑，避免重复计费。
- 已有 task_id 后查询超时 → 报告 task_id 和查询地址，可稍后手动查询；不要自动创建新任务。
- 401/403 → 只更新所选模型对应的本地密钥，不改脚本。
- ModelScope 返回 `FAILED` → 报告服务端 message/error；不要自动改用 GPT 或自动重跑。

## 成本与行为边界

- 每次只生成 1 张图，走用户所选服务账户计费；一篇文章一个比例一张图，不主动生成多张备选。
- 脚本轮询上限约 5 分钟；网络请求本身受服务端响应速度影响。
- GPT 路径请求明确的 size，但实际像素可能缩放；MiniMax ModelScope 路径目前只把比例写入提示词。两者都以脚本报告的实际尺寸和人工预览为准。
- 不配置或调用 LoRA；用户明确提出时再单独确认需求与接口支持。

## 技术备忘（脚本已封装，仅供排查）

- GPT 创建：`POST <API_BASE>/v1/images/generations`，返回 `task_id`；轮询：`GET <API_BASE>/api/image-tasks?ids=<task_id>`，图片位于成功任务的 `results[0]`。
- ModelScope 创建：`POST <MODELSCOPE_API_BASE>/v1/images/generations`，请求头含 `X-ModelScope-Async-Mode: true`；轮询：`GET <MODELSCOPE_API_BASE>/v1/tasks/<task_id>`，请求头含 `X-ModelScope-Task-Type: image_generation`，`SUCCEED` 时下载 `output_images[0]`。
- 完整配置、协议差异、验证与回滚说明见 `../docs/article-cover-generator.md`。
